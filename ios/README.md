# TVCompanion for iPhone and iPad — Phase 3

This native SwiftUI client pairs with a Google TV using its Remote v2 service and sends `alert` or `alert2` messages to the TVCompanion Android notification receiver. Mac support remains a later evaluation. It has no UxPlay, Tuya, Android command-server or third-party package dependency.

Open `TVCompanion.xcodeproj` in Xcode 16 or newer, select the `TVCompanion` scheme and an iPhone/iPad running iOS 17 or newer, then select your own development signing team for a device build. For a local simulator build:

```sh
xcodebuild -project ios/TVCompanion.xcodeproj -scheme TVCompanion -configuration Debug -destination 'generic/platform=iOS Simulator' CODE_SIGNING_ALLOWED=NO build
swift test --package-path ios/TVCompanionKit
swift test --package-path ios/TVCompanionAudio
```

The app's **Choose your TV** sheet can find the standard `_androidtvremote2._tcp.` Bonjour service, or accept a manually entered TV address. Pairing shows a six-character hexadecimal code supplied by the Google TV remote service; enter that code on the iPhone/iPad. Remote pairing and the TVCompanion message PIN are separate credentials, both held in the device Keychain. Remote control connects on the TV's Remote v2 service; the notification sender uses the TVCompanion receiver's port (default 8766). Enable notification reception and overlay permission in the Android app before sending. The user verified the latest iPhone build; iPad alternating-pairing behavior remains unrecorded.

Remote controls include D-pad/Select, Home, Back, a capability-gated Power button, volume/mute, basic playback, and a TV keyboard sheet. Focus a text field on the TV, open **Keyboard**, type and tap **Send**; **Delete** and **Enter** send TV key presses. Text uses the Remote v2 IME batch edit message and the latest field counters supplied by the TV. The TV must advertise IME support, and some apps may ignore remote text input. Each button press sends a short key event. Backgrounding the app disconnects the remote; a saved pairing reconnects automatically on return to the foreground, with bounded retries. Sending a notification creates one stable request ID, and an uncertain delivery can be manually retried with that ID. A `202 queued` receipt confirms acceptance only. The sender reports an older TV that rejects `alert2` rather than silently changing it to `alert`.

Voice is available only if the TV advertises Remote v2's VOICE feature. Tap Voice to start or stop. Once microphone access has been granted, hold Voice to talk and release to stop. The app sends 8 kHz mono PCM through the same pinned remote connection until Stop, disconnect, backgrounding or a real audio interruption. No speech is recorded to files or sent to another service. The TV's assistant may require its own account and network connection. The Power key is offered only when the TV advertises support; waking from standby still requires the TV's remote service to be reachable.

The notification API currently uses PIN-authenticated **unencrypted LAN HTTP**. Send non-sensitive messages on a trusted local network. Local network access and Bonjour browsing are declared in `Info.plist`; no automatic capture of other apps' notifications is provided. The pure `TVCompanionKit` package owns wire formats and request/response validation. The app's infrastructure owns TLS, pairing identity, discovery, Keychain and HTTP; SwiftUI views use dedicated view models. Remote TLS pins the peer key learned during pairing. This implementation is based on protocol behavior observed in [androidtvremote2 revision e664a8e](https://github.com/tronikos/androidtvremote2/tree/e664a8e1f14ee458b14c646bfb3ea46f10367051) (Apache 2.0); its source was not copied into this project. Detailed certificate-change, TV wake, and iPad alternating-pairing outcomes remain to be recorded before release.
